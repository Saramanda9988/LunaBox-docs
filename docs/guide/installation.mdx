<Callout type="idea" title="提示">

从 v2.0.0 开始，LunaBox 的界面改用 [MyGo](https://github.com/egoist/mygo) 原生渲染，不再使用 Wails 与 React 前端，开发时不需要 Node.js 前端工具链，也不需要 WebView。原来的 Wails 版本已归档在 Git 标签 `wails-final`，`wails3 dev`、`scripts/build.bat` 等命令只适用于该标签及更早的版本。

</Callout>

如果仅需安装应用，请前往 [GitHub Releases](https://github.com/Saramanda9988/LunaBox/releases) 下载发布包。

## 基础工具

| 工具 | 要求与用途 |
| --- | --- |
| [Git](https://git-scm.com/downloads) | 获取源码和版本信息 |
| [Go](https://go.dev/dl/) | 按 `apps/desktop/go.mod` 的 `go` 声明安装，当前为 `1.27.3` |
| C 编译器 | DuckDB 需要 CGO，各平台的编译器见下文 |
| [pnpm](https://pnpm.io/installation)（可选） | 仓库根目录 `package.json` 提供 `pnpm dev`、`pnpm package` 等快捷命令；不安装时可直接运行对应的 `go` 命令 |

MyGo 的命令行工具通过 `go.mod` 的 `tool` 指令锁定版本，无需单独安装。

## 配置平台环境

<Tabs groupId="lunabox-dev-platform" items={['Windows', 'macOS', 'Linux']} persist>

<Tab value="Windows">

Windows 的 MSYS2 安装与编译器配置参考 [DuckDB Go 官方文档的 Windows 要求](https://github.com/duckdb/duckdb-go#windows)。项目需要正确版本的 GCC 和相应运行库，并启用 CGO。

使用 [MSYS2 安装程序](https://www.msys2.org/)完成安装，然后打开 MSYS2 终端并执行官方要求的安装命令：

```bash
pacman -S mingw-w64-ucrt-x86_64-gcc
```

根据安装提示确认操作。如果终端在安装过程中关闭，请重新打开终端完成安装。

AMD64 环境中，编译器目标应包含 `x86_64`，Go 架构应为 `amd64`。将编译器目录（如 `C:\msys64\ucrt64\bin`）加入 Windows 用户的 `Path` 环境变量后，可在 PowerShell 中检查：

```powershell
gcc -dumpmachine
go env GOARCH
```

界面由 MyGo 通过 Direct3D 11 和 DirectWrite 绘制，运行应用不需要 WebView2。只有统计页的美化导出会使用系统的 [WebView2 Runtime](https://developer.microsoft.com/en-us/microsoft-edge/webview2/) 预览 HTML 模板，缺少时应用内会给出提示。

构建安装包时还需安装 [NSIS](https://nsis.sourceforge.io/Download)（或 `choco install nsis`），便携包不需要。

</Tab>

<Tab value="macOS">

在 macOS 终端中执行以下命令，安装 Xcode Command Line Tools，提供 Clang 和系统 SDK：

```bash
xcode-select --install

clang --version
go env GOARCH
```

Apple Silicon 使用 `arm64`，Intel Mac 使用 `amd64`，请使用与本机架构匹配的 Go 安装包。应用最低支持 **macOS 12.0**，打包工具会自动设置对应的编译目标。DMG 打包使用系统自带的 `codesign` 和 `hdiutil`。

</Tab>

<Tab value="Linux">

本文以 **Ubuntu 24.04** 为例。构建只需要 DuckDB 使用的 C 编译器，MyGo 在运行时才加载系统的 GTK 3 与 libepoxy，无需安装 GTK 或 WebKitGTK 的开发包：

```bash
sudo apt-get update
sudo apt-get install -y build-essential ca-certificates curl desktop-file-utils

gcc -dumpmachine
go env GOARCH
```

`desktop-file-utils` 供 AppImage 打包时校验桌面入口。常见的桌面环境已自带 GTK 3 与 libepoxy 运行库，请在能够显示桌面窗口的图形会话中启动应用。统计页的美化导出需要系统的 WebKitGTK，缺少时应用内会给出提示。

</Tab>

</Tabs>

## 获取源码和安装依赖

LunaBox 是一个 monorepo，桌面应用位于 `apps/desktop`，后端与更新器分别是 `packages/backend` 和 `packages/updater` 下的独立 Go 模块，桌面应用通过 `replace` 引用它们。

git clone https://github.com/Saramanda9988/LunaBox.git
Set-Location LunaBox
go -C apps/desktop mod download
```

</Tab>

<Tab value="macOS">

cd LunaBox
go -C apps/desktop mod download
```

</Tab>

## 启动开发模式

在仓库根目录执行：

```bash
pnpm dev
```

不使用 pnpm 时，在 `apps/desktop` 目录执行等价的命令：

```bash
go run ./tools/mygo dev                  # 构建并启动，代码、配置或图标修改后自动重建并重启
go run ./tools/mygo dev -lang en-US      # 本次运行使用英语界面，不写入配置
```

`tools/mygo` 会先设置 `CGO_ENABLED=1`，再运行 `go tool mygo`。`mygo dev` 会监听应用依赖的全部本地包（包括 `packages/backend`），在终端按 `Ctrl+C` 或 `q` 结束开发进程。

<Callout type="warn" title="开发数据">

开发运行使用独立的数据目录 `apps/desktop/build/data`。首次运行时会从安装版的数据目录**复制**设置、数据库、封面等数据，之后的读写都只作用于这份拷贝，不会改动安装版的数据。但备份恢复、上传到云端等操作是真实执行的，操作前请确认。

开发运行不注册开机自启、不启动 CLI 的 IPC 服务与 MCP 服务，也不自动云同步，避免影响同时运行的安装版。

</Callout>

`mygo dev` 不能向应用传递参数。需要参数时，先在 `apps/desktop` 下构建再运行：

```bash
CGO_ENABLED=1 go build -o build/LunaBox.exe .
./build/LunaBox.exe -reseed              # 重新从安装版复制数据
./build/LunaBox.exe -data-dir <目录>     # 使用其他数据目录
./build/LunaBox.exe -lang ja-JP          # zh-CN、zh-TW、en-US、ja-JP
./build/LunaBox.exe -route /settings     # 启动时打开指定页面
```

macOS 和 Linux 上将输出文件名中的 `.exe` 去掉即可。

## 测试与检查

```bash
pnpm check
```

该命令会编译桌面应用、运行更新器测试并检查更新服务。也可以分别运行：

```bash
go -C apps/desktop test ./...       # 界面测试，不打开窗口
go -C packages/backend test ./...   # 后端测试
```

界面测试使用 MyGo 的 `ui.Tester` 构建视图、模拟输入和推进时钟，每个测试都会在临时目录中新建数据库并执行全部迁移。修改 `apps/desktop/ui/locales/*.json` 后，请运行 `pnpm i18n` 重新生成语言包代码。

## 构建和打包

发布包由 `apps/desktop/tools/release` 构建。在仓库根目录执行 `pnpm package`，或在 `apps/desktop` 下执行：

```bash
go run ./tools/release                                          # 当前系统的默认包，架构 amd64
go run ./tools/release -version 2.0.0 -arch arm64 -mode installer
```

| 参数 | 说明 |
| --- | --- |
| `-version` | 版本号，省略时使用最近的 `v` 前缀版本标签 |
| `-arch` | 目标架构，支持 `amd64` 和 `arm64`，默认 `amd64` |
| `-mode` | 发布包的种类，见下文各平台的说明 |

目标系统始终是当前系统：DuckDB 需要 CGO，不能交叉编译。打包工具会编译桌面程序、命令行工具 lunacli 和独立更新程序，并将仓库 `apps/desktop/lib/` 中对应平台的 7z 一起放入发布包，请保留这些文件。产物位于 **`apps/desktop/build/release/`**。

可执行文件的文件版本与安装包版本取自 `apps/desktop/mygo.json` 的 `version`，正式发布前请将其改为要发布的版本。

<Tabs groupId="lunabox-dev-platform" items={['Windows', 'macOS', 'Linux']} persist>

<Tab value="Windows">

| `-mode` | 产物与数据目录 |
| --- | --- |
| `portable`（默认） | 便携 ZIP，数据存储在程序目录 |
| `installer` | NSIS 安装程序，数据存储在 `%APPDATA%\LunaBox`，需要 NSIS |
| `installer-payload`、`installer-package` | 将 `installer` 拆成两步，便于在中间为可执行文件签名 |

```powershell
go run ./tools/release -version 2.0.0 -mode portable
go run ./tools/release -version 2.0.0 -mode installer
```

```text
build/release/LunaBox-2.0.0-windows-amd64-portable.zip
build/release/LunaBox-2.0.0-windows-amd64-setup.exe
```

**Windows ARM64 打包**

ARM64 打包需要面向 ARM64 的 CGO 编译器。在 MSYS2 的 **CLANGARM64** 终端中安装工具链：

```bash
pacman -S --needed mingw-w64-clang-aarch64-toolchain
```

打包工具会在 `MSYS2_LOCATION` 或默认的 `C:\msys64` 下查找 `clangarm64/bin/clang.exe`，也可以通过 `CC` 指定编译器：

```powershell
$env:MSYS2_LOCATION = "C:\msys64"
go run ./tools/release -version 2.0.0 -arch arm64 -mode installer
```

ARM64 版本动态链接仓库中的 `lib/winarm64/duckdb.dll` 和 `duckdb.lib`，发布包会附带运行所需的 DuckDB 动态库。

</Tab>

<Tab value="macOS">

macOS 只有 `installer` 一种模式，生成 DMG。以 Apple Silicon 为例：

```bash
go run ./tools/release -version 2.0.0 -arch arm64
```

Intel Mac 将 `arm64` 替换为 `amd64`。打包工具会生成 `LunaBox.app`，在 `Contents/Resources/bin` 中补上 lunacli 与 7zz，进行本地临时签名（ad-hoc）后生成 DMG：

```text
build/release/LunaBox-2.0.0-macos-arm64.dmg
```

正式的开发者签名与公证暂未接入打包流程。

</Tab>

<Tab value="Linux">

**安装发布打包工具**

DEB 和 RPM 打包使用 [nFPM](https://github.com/goreleaser/nfpm)，AppImage 打包使用 [appimagetool](https://github.com/AppImage/appimagetool)：

```bash
go install github.com/goreleaser/nfpm/v2/cmd/nfpm@latest
nfpm --version

curl -fsSL \
  https://github.com/AppImage/AppImageKit/releases/download/continuous/appimagetool-x86_64.AppImage \
  -o /tmp/lunabox-appimagetool-x86_64.AppImage
sudo install -m 0755 /tmp/lunabox-appimagetool-x86_64.AppImage /usr/local/bin/appimagetool
export APPIMAGE_EXTRACT_AND_RUN=1
appimagetool --version
```

`APPIMAGE_EXTRACT_AND_RUN=1` 允许打包工具解压后运行，适用于缺少 FUSE 挂载支持的构建环境。ARM64 请改用 `appimagetool-aarch64.AppImage`。

**生成 Linux 发布包**

| `-mode` | 产物 |
| --- | --- |
| `appimage`（默认） | AppImage，数据存储在 `~/.config/LunaBox` |
| `installer` | DEB 和 RPM |
| `all` | DEB、RPM 和 AppImage |

```bash
go run ./tools/release -version 2.0.0 -mode all
```

```text
build/release/LunaBox-2.0.0-linux-amd64.AppImage
build/release/LunaBox-2.0.0-linux-amd64.deb
build/release/LunaBox-2.0.0-linux-amd64.rpm
```

发布包在运行时依赖系统的 GTK 3 与 libepoxy。

</Tab>

</Tabs>

<Callout type="info" title="兼容旧版本">

发布包的文件名与包内布局沿用 Wails 版本，应用内更新依赖这一约定。安装版（Windows 安装包、DEB、RPM、DMG）会安装到 Wails 版本的位置并使用相同的卸载项与包名，可以直接覆盖已安装的旧版本。

</Callout>

## 可选的第三方服务配置

需要调试第三方授权或 API 功能时，复制 `apps/desktop` 下的配置模板：

<Tabs groupId="lunabox-dev-platform" items={['Windows', 'macOS', 'Linux']} persist>

<Tab value="Windows">

```powershell
Copy-Item apps/desktop/.env.build.example apps/desktop/.env.build
```

</Tab>

<Tab value="macOS">

```bash
cp apps/desktop/.env.build.example apps/desktop/.env.build
```

</Tab>

<Tab value="Linux">

```bash
cp apps/desktop/.env.build.example apps/desktop/.env.build
```

</Tab>

</Tabs>

按模板填写所需服务的配置。开发运行会读取 `apps/desktop` 下的 `.env.build` 和 `.env`；打包工具优先使用 `LUNABOX_*` 环境变量，未设置的项再从 `.env.build`、`.env` 读取，并注入到发布程序中。未配置时，依赖这些凭据的授权功能（如 Bangumi、鲲 Galgame 登录）不可用，其余功能可以正常开发。
